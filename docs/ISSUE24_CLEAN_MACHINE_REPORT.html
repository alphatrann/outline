1. Summary

The K16 integration suite is not green on Windows. The harness itself works: on a fresh clone it starts disposable Postgres 17 and Redis 8 containers, applies every migration, runs the suite and removes the containers. But 4 of 53 tests fail, and all four are the revisions flow (K16 Flow 3). The same four failures reproduce on the supported Node 22.16, so they are not caused by Node 26.

The only setup blocker is that Node 26 no longer bundles Corepack, so yarn is missing on a clean install until Corepack is installed manually. After that, yarn install --immutable and yarn test:integration run normally.

2. Scope and method

K16 is an integration-testing deliverable, not a unit-test deliverable. The K16 plan is scope-locked to four flows and makes yarn test:integration the binding command:

  • K16 plan §1.6: “Scope-locked. Only the 4 flows in §2. Everything else is mocked or excluded.”
  • K16 plan §5: “Pass = … 3 consecutive green runs of yarn test:integration for the touched files.”
  • README, Integration tests: “Run the whole suite with one command: yarn test:integration.”

This report therefore covers only the committed integration suite at 6e780a9 — the five files listed in section 3. The general unit-test section of the README (make test / yarn test) is outside Deliverable H and is not reported here. Uncommitted local test files are also excluded.

No rerun. This revision reuses the integration-only run captured during the clean-machine session. The Node 26 and Node 22 logs are the evidence; the suite was not executed again for this report.

7. Gaps found

ID Severity Gap Evidence Suggested fix (owner T)
G1 P1 Node 26 no longer ships Corepack, so the README’s yarn install --immutable cannot run on a clean machine. The README never says how to install Yarn/Corepack. corepack --version and yarn --version are unrecognised with Node 26.13.1. Installing corepack@0.36.0 from npm fixes it. Add an explicit prerequisite step: npm install -g corepack@0.36.0 && corepack enable, or pin Node 24 in .nvmrc.
G2 P1 K16 Flow 3 (revisions) is red on Windows: 4 of 53 integration tests fail, all in revisions.integration.test.ts. No revision appears within 15 s/30 s; the same four tests fail on Node 26.13.1 and Node 22.16. The other four integration files pass. Investigate the Bull worker / revision queue startup under Windows, then rerun the suite three consecutive times per K16 §5.
G3 P2 README integration success example is stale. README: 2 test files / 3 tests / 72.79 s. Current suite: 5 files / 53 tests / 172.19 s. Refresh the example with the current counts and duration.
G4 P2 .nvmrc 26 resolves to Node 26.13.1, which is outside package.json engines (26 <26.3.1). CI installs from the engines field, not .nvmrc, so local and CI toolchains differ. Local node -v: v26.13.1; the manifest allows only 26.0.0 <= version < 26.3.1 on the 26 line. Pin .nvmrc to 26.3.0 (or 24), or widen the engines range after testing 26.13.x.
G5 P3 The issue pins SHA 05ef55e, but that commit predates the Testcontainers harness (PR #7) and the integration README section (PR #35), so it cannot be the target of an integration run. 05ef55e is from 2026-09-29; PR #7 merged 2026-10-06 and PR #35 merged 2026-10-19. This run used 6e780a9 (2026-11-19). Update the pinned SHA in the sprint issue template.

8. What works

  • Cold yarn install --immutable succeeds after the Corepack step: 2,108 packages, 1.04 GiB, 19 m 44 s.
  • Testcontainers boots disposable Postgres 17 and Redis 8 containers, applies every migration, and removes the containers at the end.
  • Four of the five integration files pass: collections, documents, shares and users — 49 of 53 tests.
  • No .env is required; the committed .env.test is sufficient. The documented configLoader: 'native' warning appears and is harmless.
  • The same four revision failures reproduce on Node 22.16, so the green Linux CI at the same commit confirms they are Windows-specific rather than a broken main branch.

10. Limitations

  • No rerun. This revision reuses the integration-only run captured earlier. One run per Node version is reported; the K16 “3 consecutive green runs” criterion is not met because the suite is red.
  • Not a freshly installed OS: the same Windows 11 machine was used, with Docker Desktop and the postgres:17/redis:8 images already present. The Yarn cache was cold, but image pulls were not exercised.
  • Node 26.13.1 is the local resolution of .nvmrc 26; CI uses the package.json engines range and therefore a different 26.x patch.
  • Windows-only run. Linux CI is green but was not reproduced locally.
  • Uncommitted local test files are not part of the five-file suite at 6e780a9 and are not included in this report.
