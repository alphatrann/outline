4. Gaps found

ID Severity Gap Evidence Suggested fix (owner T)
G1 P1 Node 26 no longer ships Corepack, so the README's yarn install --immutable cannot run on a clean machine. The README never says how to install Yarn/Corepack. corepack --version and yarn --version are unrecognised with Node 26.13.1. Installing corepack@0.36.0 from npm fixes it. Add an explicit prerequisite step: npm install -g corepack@0.36.0 && corepack enable, or pin Node 24 in .nvmrc.
G2 P1 The only README full-suite command is make test. GNU Make is not part of a standard Windows install, and the test-database commands exist only inside the Makefile. make : The term 'make' is not recognized.... The manual equivalent (docker compose up -d postgres and yarn sequelize ...) works but is undocumented. Add a platform-neutral script (for example yarn test:all) or document the Windows/manual commands next to make test.
G3 P1 yarn test (and therefore make test) always includes the server-integration project, so it needs Docker and starts Testcontainers. The README presents the integration suite as a separate command and warns about running it alongside make test. vitest.config.ts lists server-integration in the default projects; the full run executed revisions.integration.test.ts. Clarify that the full suite requires Docker, or split an aggregate test:all (unit + integration) from a unit-only test.
G4 P1 Missing .gitattributes: with core.autocrlf=true, Git converts 2,694 files to CRLF on checkout. This corrupts binary PDF fixtures, breaks the LF-only frontmatter regex, and leaves 13 committed snapshots modified after a test run. document.pdf is 801 B in Git but 839 B in the worktree; scanned.pdf is 442 B → 470 B. markdown-frontmatter.md starts with 2D 2D 2D 0D 0A and fails /^---\n([\s\S]*?)\n---(?:$|\n)/. git status shows 13 modified .snap files with an empty git diff. Add .gitattributes with * text=auto eol=lf, *.pdf binary, *.docx binary and *.snap text eol=lf, and make processFrontmatter accept CRLF.
G5 P2 README success example is stale. README: 2 test files / 3 tests / 72.79 s. Current integration suite: 5 files / 53 tests / 172.19 s. Current full suite: 390 files / 5,451 tests. Refresh the example with the current counts and duration.
G6 P2 .nvmrc 26 resolves to Node 26.13.1, which is outside package.json engines (26 <26.3.1). CI installs from the engines field, not .nvmrc, so local and CI toolchains differ. Local node -v: v26.13.1; manifest allows only >=26.0.0 <26.3.1 on the 26 line. Pin .nvmrc to 26.3.0 (or 24), or widen the engines range after testing 26.13.x.
G7 P1 The suite is not Windows-portable. 30 persistent failures: 14 path-separator assertions, 4 storage-key 400s, 4 cron 500s, 3 PDF fixture failures, 1 frontmatter failure and 4 revision integration timeouts. See section 5 for the per-file inventory. Use POSIX / in Markdown links and storage keys, fix the cron dynamic import, and investigate the revision worker under Windows.
G8 P3 A test run rewrites 13 committed snapshot files with LF. With core.autocrlf=true they appear as modified although the content diff is empty. git status --porcelain: 13 modified .test.ts.snap files; git diff --numstat: 0 lines. Same .gitattributes fix as G4.
G9 P3 The issue pins SHA 05ef55e, but that commit predates the Testcontainers harness (PR #7) and the integration README section (PR #35), so it cannot be the target of a suite run. 05ef55e is from 2026-09-29; PR #7 merged 2026-10-06 and PR #35 merged 2026-10-19. This run used 6e780a9 (2026-11-19). Update the pinned SHA in the sprint issue template.

Per the team's instruction for this run, no separate GitHub issues were created for these gaps. They are recorded here and summarized in the issue #24 comment; the recommendation is to file them under owner T after review.

6. What works

  • Cold yarn install --immutable succeeds after the Corepack step: 2,108 packages, 1.04 GiB, 19 m 44 s.
  • The Makefile's database steps work when run manually; migrations apply cleanly to outline-test.
  • Integration tests start disposable Postgres 17 and Redis 8 containers, migrate them, and clean up. 49 of 53 tests pass, including the other four integration files.
  • 5,390 of 5,451 tests pass (98.9%), and the app project has no failures; the failures are confined to server/shared Windows behaviour and the revision integration worker.
  • No .env is required; the committed .env.test is sufficient. The documented configLoader: 'native' warning appears and is harmless.
  • Linux CI is green at the same commit, so the 30 persistent failures are Windows-specific rather than a broken main branch.

7. Recommendations for T

  1. G1: add the Corepack/Yarn prerequisite to the README (and the onboarding guide), or pin Node 24.
  2. G2/G3: provide a cross-platform test command and document the test-database setup; state clearly that the full suite includes Testcontainers and needs Docker.
  3. G4/G8: add .gitattributes so binary fixtures are never converted, force LF for .snap files, and make the frontmatter parser CRLF-tolerant.
  4. G7: fix Windows path handling in Markdown link/key rewriting (14 + 4 tests), the cron @shared/types import (4), and the revision worker tests (4).
  5. G5/G6: refresh the README output example and align .nvmrc with the engines range and CI.
  6. G9: update the issue template's pinned SHA so future clean-machine tasks target a commit that contains the harness.

8. Limitations

  • Not a freshly installed OS: the same Windows 11 machine was used, with Docker Desktop and the postgres:17/redis:8 images already present. The Yarn cache was cold, but image pulls were not exercised.
  • Node 26.13.1 is the local resolution of .nvmrc 26; CI uses the package.json engines range and therefore a different 26.x patch.
  • Windows-only run. Linux CI is green but was not reproduced locally.
  • The Node 22 comparison covered the 11 failing unit files and the integration suite, not the entire 5,451-test run.
  • Three full-run timeouts passed in isolation; they are reported as load flakes, not as reproducible failures.
  • make was not installed, so the literal README path stops at make test; later steps used the Makefile's commands manually.
