K16 Technical Plan — Ephemeral Integration Testing (Deliverable D)

Issue #14 · Owner: H (gsb-b60) · Sprint 2 (Oct 8 – Oct 20, due Oct 17) · Base: origin/main with harness from PR #7 · Supersedes Sprint 1 draft (docs/k16-principles.md at ae00f8951, removed in ca4329304).

K16 = run the integration suite against disposable Postgres + Redis containers (Testcontainers) instead of mocks. This plan finalizes the principles, scope rationale, assumptions, risks, and pass/fail criteria for the 4 fixed flows described in Codebase Guide §4.

1. Principles (final)

  1. Hermetic Postgres + Redis per run. server/test/containers.ts (startContainers()) boots postgres:17 and redis:8 (pinned, matching docker-compose.yml), applies all migrations from server/migrations/, then exposes DATABASE_URL/REDIS_URL via server/test/globalSetupContainers.ts once per run. Containers stop on global teardown.
  2. Migration-seeded, trigger-faithful. Real migrations keep documents_search_trigger() (tsvector title(A) / previousTitles(C) / text(D)), required for Flow 4 ranking. Seeds come from server/test/factories.ts (buildTeam/buildUser/buildCollection/buildDocument/buildShare), never hand-edited fixtures.
  3. API-boundary tests. Drive POST /api/* through getTestServer() (server/test/support.ts, TestServer.ts) with API-token auth; assert presenter shape + status codes, then assert DB rows — not internal function calls. Pattern: server/routes/api/users/users.integration.test.ts.
  4. Deterministic async. Revision creation is debounced: server/queues/processors/DebounceProcessor.ts delays documents.update by (isProduction ? 5 : 0.5) * 60 * 1000, then RevisionsProcessor skips deep-equal latest. Tests poll Revision.findLatest(documentId) instead of fixed sleeps; Bull uses the ephemeral Redis.
  5. Serial + fast teardown. Vitest project server-integration (vitest.config.ts): server/**/*.integration.test.ts, fileParallelism: false, testTimeout: 30000, hookTimeout: 120000. server/test/cleanup.ts (cleanBetweenTests()) truncates every table except SequelizeMeta and runs flushall before each test. No S3/MinIO/network; setupIntegration.ts keeps only @aws-sdk/franc/request-filtering-agent/dd-trace mocks and does not mock ioredis/bull. Docker host autodetect (configureDockerHost()) covers Colima/Rancher/rootless.
  6. Scope-locked. Only the 4 flows in §2. Everything else is mocked or excluded (see limitations in Codebase Guide §7).

3. Assumptions

  • Auth = pre-seeded user + API token for all flows (no login flow under test).
  • SEARCH_PROVIDER=postgres (default); migrations applied so the tsvector trigger exists.
  • Docker available for yarn test:integration; unit suite (yarn test:server) needs no Docker and excludes *.integration.test.ts.
  • Tests seed via factories + migrations; no shared DB state between runs or files.
  • Docs-only deliverable: no app/server code changes, no new i18n strings, yarn format clean.

5. Pass/fail criteria (binding)

  • Pass = HTTP status + presenter shape and DB-row assertion in the same test (e.g. 200 + body.data.name + User.findByPk), independence via cleanBetweenTests(), and 3 consecutive green runs of yarn test:integration for the touched files.
  • Fail = any of: wrong status/shape, DB row missing or stale, data visible across tests, timeout (>30s test / >120s hook), container boot failure, or flaky 1-of-3.
  • Evidence per PR: command + full log + machine/Docker info + timings. Counts toward #12 (Flow 1), #18/#19 (Flows 2–3 expansion), and #21 (one-command run doc).
yarn test:integration server/routes/api/users/users.integration.test.ts
