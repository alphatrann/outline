Verdict

The tests run and pass and catch real breakage, but mutation testing (31.65% of mutants killed, measured on the original 45 tests) shows they are still thin. Of 6 deliberate authorization/isolation breakages, 4 went unnoticed by the original 45 tests. Three of those are now covered by 4 new tests (all pass against the real code, so the permissions work); the fourth is a redundant check. Line coverage alone would have hidden this (the policies show ~90%).

Caveat: only the whole suite was run per break, so a "not caught" means no test in any file failed. The two "caught" tests listed are the ones that failed in the delete and lock runs.

Tests added in response

  • documents.move: user who can write the destination but only read the source gets 403 and the document stays put.
  • documents.archive: read-only member gets 403, archivedAt stays null.
  • collections.info: another team's user cannot read an open (ReadWrite) collection.
  • shares.create: another team's user cannot share a document; no share row is created.

All four pass against the unmodified code, so no permission bug was found. The first three fail when their safeguard is removed (re-verified with the same deliberate-breakage procedure).
