How mutation testing works

Stryker creates many copies of the production code, each with one small fault, and runs the tests against each. A mutant is killed if a test fails and survived if all pass; a survivor is a change the tests cannot see. Score = (killed + timeout) / all mutants.

To avoid recompiling 695 times, Stryker rewrites each file once and wraps every fault in a switch, then activates one id per run. The rewritten code in the working tree is temporary and restored afterwards. 

original:    if (!collection || user.teamId !== collection.teamId) { return false; }
mutant 174:  if (false) { return false; }     // cross-team check removed

3. Manual breakage

Each safeguard was removed from production code, the full integration suite run, and the change reverted.

Safeguard removed Result Test that fails
Row lock in RevisionsProcessor Caught revisions: concurrent identical updates create one revision
authorize(delete) in documents.delete Caught documents: read-only member cannot move, update or delete; collections: cross-team update, move or delete
authorize(move) in documents.move Caught documents: cannot move out of a collection the user can only read
authorize(archive) in documents.archive Caught documents: read-only member cannot archive
authorize(createShare) in shares.create Not caught Redundant: guests and other teams are also denied by the document check, and isTeamMutable always returns true. Likely defence in depth, so no test was added.
Cross-team check in collection read policy Caught collections: another team cannot read an open collection

“Not caught” means no test in any file failed. The move, archive and cross-team collection tests were added because the original suite missed these breaks.

Tests added from these findings

  • documents.move: user who can write the destination but only read the source gets 403; the document stays.
  • documents.archive: read-only member gets 403; archivedAt stays null.
  • collections.info: another team's user cannot read an open collection.
  • shares.create: another team's user cannot share a document; no share row is created.
  • Document policy: a collection-less draft is private to its creator.
  • Document policy: Read membership reads but cannot edit; ReadWrite edits but cannot invite.
  • Document policy: viewers export only when the team allows it.
  • Document policy: commenting is rejected team-wide (400) and per collection (403).

All pass against unmodified code, so no permission bug was found.

Limits

  • Stryker runs with inPlace: true because its sandbox crashes on TypeScript 7 (ts.parseConfigFileTextToJson is not a function). It edits source files during the run and restores them afterwards. Do not run it with uncommitted changes in the mutated files or alongside other test runs.
  • Each Stryker configuration ran once; no flakiness repeats. The full integration suite passed twice in a row (215 tests). The route run mutated only the line ranges of the handlers listed in 2b.
  • Equivalent-mutant labels come from reading the code. The ability matrices record current behaviour; where a row looks wrong it is listed above, not changed.
